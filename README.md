# Tennis Form Analyzer

## v63: 高速ヒットポイント検出

- 画面を「ヒットポイント」タブに限定
- 音声候補ごとに `-0.1秒 / 候補時刻 / +0.1秒` の3枚だけMediaPipe Poseを実行
- 右手首・右肘・右肩から、サーブまたは腰付近のストローク動作を確認
- 姿勢変化のない壁音・環境音候補を除外
- サーブは右手首の最高点、ストロークはカメラ方向に応じた体中心との距離で打点を局所探索
- 局所探索は1フレームずつ行い、改善が止まれば終了
- MediaPipeが人物を取れない候補は誤削除を避けるため「不確実」として保持
- 全HPに対する従来の長時間MediaPipe自動検出は停止

PowerShellでは、初回に `./setup.ps1`、以後は `./run.ps1` で起動する。

## v64: ヒットポイント詳細

- 「ヒットポイント一覧」と「ヒットポイント詳細」の2タブ構成
- 一覧の選択HPをオレンジで強調し、詳細タブと同期
- 姿勢の粗判定を `-0.3秒 / 候補 / +0.3秒` に変更
- 3枚をMediaPipeキーポイント範囲＋パディングで自動クロップ
- Refinerと同じ色・形状のキーポイントマーカーを重ねて表示
- 候補前後2秒のサウンドエネルギーと3フレーム位置を表示
- サーブ、ストローク、壁音除外、安全保持の4判定を表示

## v65: 候補監査と音声フィルター比較

- 詳細タブは検出時の正確なフレーム番号を使い、3画像のKPずれを防止
- 一覧タイムラインに前後2秒の「拡大／元に戻す」トグルを追加
- 現在HP前後1秒の候補を、採用は緑丸・不採用は赤丸で表示
- 赤丸のマウスオーバーで、不採用理由・手首移動量・肘角度変化を表示
- 周波数フィルターON/OFFを追加し、フィルター済み合成エネルギーと
  広帯域サウンドエネルギーを切り替えて候補を再判定

## v66: 同一画像KP表示と閾値可視化

- MediaPipeへ渡した実画像を保持し、その同一画像へKPを重ねてシークずれを排除
- 詳細タブの音声グラフにも採用候補（緑丸）と不採用候補（赤丸）を表示
- 一覧・詳細の両音声グラフへ、現在の検出感度から求めた閾値線を表示
- 検出設定の「適用してHPを再判定」で音声候補とMediaPipe姿勢を再実行

テニスフォーム分析デスクトップアプリ。動画からヒットポイント（HP）を音声解析で検出し、YOLO/MediaPipe による姿勢推定・3D 可視化・KP 手動洗練までを行う。

## プロジェクトの目的

テニス動画（練習・試合・壁打ち）を入力として、以下を可能にする：

- 音声ピーク検出によるヒットポイント（HP）の自動抽出
- 各 HP のショット分類（サーブ / フォアハンド / バックハンド / ボレー / スマッシュ / リターン等）とラベル付け
- YOLO（COCO 17 点 + 独自 3 点） / MediaPipe（33 点 + 3D 座標）によるキーポイント推定
- MediaPipe Face Mesh による顔 KP の高精度化
- Refiner による KP の手動編集と学習 DB への蓄積
- 3D スケルトンの可視化と動画フレームとの重ね合わせ
- MP-YOLO 検出結果の比較
- 連続写真、時系列グラフ、XY 軌跡グラフによる分析

## 現在完成している機能

### メイン画面
- 動画情報ポップアップ（1 秒おき 10 秒進みでサムネイル自動切替、日付時間表示、カメラ方向、主なショット、内容、MediaPipe 自動検出チェック）
- 音声解析による HP 自動抽出
- 壁打ちモード時の連続ピーク除去（0.15〜0.45 秒内の 2 番目を除去）
- HP リスト表示・分類ラベル付け・削除
- 通常再生 / コンパクト再生（最初の HP から） / スロー再生
- タイムライン表示、字幕表示
- クロップ設定
- 進捗表示（メイン画像中央に金色表示）
- 履歴タブ（解析済み動画の一覧、サムネイル、ジャンプ）

### KP 検出
- YOLO 姿勢推定（`_cp{rank}_yolo.json` に保存）
- MediaPipe 姿勢推定（`_cp{rank}_mp.json` と `_cp{rank}_mp3d.json` に保存、バックグラウンド実行、進捗表示）
- Face Mesh 補正（0.5 秒間隔でサンプリング、前後線形補間）
- 顔・体の向き検出（face_yaw / face_pitch / body_yaw）
- ヒットフレーム最適選択（右手首の動きから真の打点時刻を推定）
- 見えない KP の自動判定（顔向きから遮蔽 KP の信頼度低下）

### Refiner（統合タブ）
- 総合ビュー（グラフ 1: 時系列、グラフ 2: XY 軌跡、グラフ 3: 角度、連続写真）
- グラフの表示トグル、グラフ 2 拡大モード
- 連続写真の開始 / 終了 / 間隔プルダウン（実データ範囲に自動調整）
- 編集タブ（KP のドラッグ移動、削除、追加、Tキーで見えない点トグル）
- KP マーカー形状: 左 = ○、右 = □、鼻 = ◇、ラケット / ボール / 重心 = ★、見えない点 = 白 × を上乗せ
- 洗練処理（Savgol 平滑化、リンク偏差検出、加速度異常検出、ラケット / ボール置換）
- 学習 DB との連携
- パラメータ調整ポップアップ
- 保存機能（`_refined.json`）

### 3D タブ（トップバー配置）
- MediaPipe 3D 検出（起動時からタブは表示、Refiner 構築時に中身が有効化）
- 3D スケルトン表示（matplotlib）
- 右パネルに 2D 写真 + KP マーカー
- MP 比較（× マーカー）
- 地面固定、実移動、カメラ視点リセット（動画情報のカメラ方向を反映）
- 保存済み 3D データの自動読込

### MP-YOLO 比較タブ（v62 追加）
- 3D タブと履歴タブの間
- 選択中 HP のフレームを大きく表示
- ○ = MediaPipe、× = YOLO を同じ画像に重ね描き
- フレームスライダーで移動

### その他
- ショット比較タブ（複数 HP を並べて比較）
- 同タイミング比較タブ
- 連続写真タブ
- プロジェクトフォルダ集約管理（`managed_videos/{stem}/`）
- MediaPipe / TF / absl の警告抑制（`_suppress_stderr` による OS レベルの stderr リダイレクト）
- 起動時最大化（zoomed）
- 検出情報パネル（左パネル下: 画像 / MP / YOLO の 3 行、検出ボタン付き、済ならグレーアウト）

## 未完成の機能と既知の問題

1. **Refiner の写真エリアがグラフ非表示時に最大化されない** — グラフ 2/3 を OFF にしても写真エリアが小さいまま。次の v63 で対応予定
2. **v62 の動作未確認項目** — 以下は実装済みだがユーザー動作確認未実施
   - HP 選択ハイライトの再生中維持
   - 3D タブの現在 HP 表示（金色大文字）
   - 画像抽出完了時の検出情報自動更新
   - YOLO 検出済み時に「✅ 検出済 (19 フレーム)」表示
   - MP-YOLO 比較タブ
3. **タブインデックスの一貫性** — v62 でタブが 1 つ増えた（比較タブ）ため、内部のインデックス（`idx==5`, `idx==6`, `idx==7`）を再確認する必要がある
4. **Tkinter フォーカス** — Refiner 編集画面での T キー動作は `editor_canvas.focus_set()` が必要。クリックで発火するが、確実性は環境依存
5. **MediaPipe の全 HP 自動検出** — 動画情報で ON にすると音声解析後に全 HP を順次検出するが、時間がかかる（1 HP あたり数秒〜十数秒）。中断機能なし
6. **プロジェクトフォルダ管理** — v40 で実装したが、実際の運用テストは未実施
7. **文字化け** — `optimal_hit_reason` を検出情報から削除済み（v43）だが、他の日本語文字列に文字化けリスクが残る可能性
8. **既知のクロップアルゴリズム制限** — サーブの上方向 40% パディングは実装済みだが、実写での確認が必要
9. **不明**: 手ぶれ判定の閾値の妥当性、履歴タブのサムネ生成タイミング

## 設計上の重要な判断

### アーキテクチャ
- `tennis_analyzer.py` に `TennisApp` (`tk.Tk`) と `RefinerFrame` (`tk.Frame`) を統合。旧 `yolo_refiner_gui.py` は単体でも動作するが、統合版が主。
- YOLO と MediaPipe は完全独立のファイル（`_yolo.json` / `_mp.json`）に保存（v62 で分離）。両者の 2D 座標は同じ COCO 17 点形式で保存され、Refiner が同じロジックで扱える。
- 3D 世界座標は `_mp3d.json` に別ファイルで保存。
- Refiner の 3D タブは `TennisApp` のメイン Notebook の子として作成される（Refiner 内 Notebook ではエラーになるため）。v58 以降。

### データフロー
```
動画 (.mp4)
  └─ ①音声解析 → HPリスト (メイン画面が動作可能)
      ├─ ②YOLO検出 → _cp{rank}_yolo.json
      ├─ ③画像抽出 → Refiner の frames_cache (メモリ)
      └─ ④MediaPipe検出 → _cp{rank}_mp.json + _cp{rank}_mp3d.json
             （③に依存: frames_cache の画像を入力にする）
```

### KP フォーマット
- YOLO: COCO 17 点 (0-16) + ラケット先端 (17) + ボール (18) + 重心 (19) = 20 点
- MediaPipe: 33 点だが、`MP_TO_COCO` 対応表で COCO 17 点に変換して保存
- JSON 内は `kp{XX}_x`, `kp{XX}_y`, `kp{XX}_c` 形式
- `person_bbox`, `obj_conf` も含む

### マーカー形状（v47〜）
- `KP_SHAPES` 配列で一元管理
- 左 = circle、右 = square、鼻 = diamond、ラケット / ボール / 重心 = star
- 推論 KP は白い × を上乗せ

### 警告抑制（v45〜）
- 環境変数 `TF_CPP_MIN_LOG_LEVEL`, `GLOG_minloglevel` を import 前に設定
- `absl.logging` を FATAL に
- `_suppress_stderr()` コンテキストマネージャで C++ レベルの stderr を OS レベルでリダイレクト

## 動作確認の方法

1. `python tennis_analyzer.py` で起動
2. 動画ファイル選択 → ポップアップで「MediaPipe 検出」チェック ON → OK
3. 音声解析完了 → HP リスト表示
4. 任意の HP を選択 → 左パネル下の検出情報が更新される
5. Refiner タブ → 総合ビューで KP と写真の重なりを確認
6. 3D タブ → HP 番号が金色で表示、右に 2D 写真、左に 3D スケルトン
7. MP-YOLO 比較タブ → ○ と × が同じ画像に重ね描き
